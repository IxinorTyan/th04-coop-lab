# 三人联机与逐阶段 Boss 耐久（2026-10-03）

**后续修正：** 下文固定 12 KiB 槽、385536 字节堆和数据段 0x2434 已由 [启动内存预算修正](three-player-boot-fix.md) 替代；当前按实际 payload 对齐并维持修改前总预算。

本轮仅代码、静态检查与构建；未执行测试、模拟器、浏览器或试听。下列机制为实现和二进制分析结果，不代表实际运行验收。

## 房间与同步

协议 `th04-lockstep/2`。房主配置 players=2/3，另有 p1/p2/p3 机体设置；配置只在大厅修改。开启三人后，host/guest/guest2 都必须存在、占据不同座位并准备。关闭三人前，需要第三个加入者离开，并腾出 P3 座位。开局后断线结束整局，不修改人数或 Boss 倍率。

每对玩家建立可靠有序 DataChannel，共三条连接；固定角色次序决定 offer 发起者。信令服务器验证来源身份、目标身份及会话，按目标投递。每人直接把自己的输入传给另外两人，无主机转发额外一跳。FrameQueue 按座位维护 2/3 条队列，缓存 2 步；任何一条缺失都不执行该步。每 120 步与每个同伴比较同一模拟步的内存和暂停状态。全员就绪与跨连接 ready 到达顺序分别处理，客机收到 run 可等剩余连接准备完成。

暂停只消费已同步输入；模拟器停止推进，网络输入继续。所有客机确认都表示继续，即使房主已选退出。房主退出后，等待两个客机各自关闭游戏并确认，再断开房间。身份与座位独立。

## 原生第三玩家

`coop.asm` 的资源表仍为 4×16 字节，实际开局人数 2/3。`three-player.asm` 保存第三人的运动、受击、子机、爆炸、激光、环弹及独立擦弹状态。guest_slot 选择当前 inactive 工作槽，active_p2 这个历史字段现在存放实际玩家编号 0/1/2。

玩家更新、绘制、背景失效、激光更新／绘制与普通碰撞通过 for_guests 遍历 P2/P3，回调前后均恢复 P1 的原版全局上下文，外层结束恢复 P2 工作槽。世界、普通子弹池、道具奖励只执行一次。拾取、瞄准、存活检查、团队奖励、HUD 使用实际人数。当前常规子弹池容量仍为原版 68，没有额外扩容。

键盘／手柄输入写入各自固定 mailbox，**输入本身不随工作槽交换**，避免模拟器一个步长停在交换代码中途时写错人。擦弹和弹龄数组直接按 guest_slot 寻址，避免每次绘制搬运 880 字节。只交换 57 字节的角色上下文。

两种角色的 BFT / Bomb 资源各预载一次。任意玩家按自身机体选择原版或备用描述符，不按 P2 身份固定。P3 无需第三套图像分配，现有 385536 字节堆预算不变。P3 的额外状态与代码使 EXE 插入槽从 8192 变为 12288 字节；额外常规内存和实际关间加载仍待人工检查。

GAP=0x3000，近代码段起点仍为 0x0AAF，payload org=0x85F0，末端不跨 64 KiB；数据段为 0x2434。构建器对原文件哈希、替换字节、重定位空间和 payload 容量进行校验。声音补丁现在读 patch.insert_size，不能继续硬编码 0x2000。配置为 `[2,rank,lives,bombs,p1char,p1shot,p2char,p2shot,p3char,p3shot,count]`，共 11 字节，同时写 MAIN 和 COOP.COM。

救人者在原 36×44 范围内选最近有效队友，同距取较小编号；目标变化清空进度。保持低速停火 90 游戏帧成功。给活人命只扣备用命，救幽灵另扣 ceil(Bomb/2)，0 Bomb 仍允许救；幽灵复活和过关复活 Bomb=1。三条进度占用文字行 0–2，不覆盖高分栏。

## Boss 阶段 HP 分析

原始 MAIN 中 Boss.hp 位于 DS:53D6，phase=53D9，phase_frame=53DA，phase_end_hp=53E0。普通阶段在扣伤害后比较 hp 与 phase_end_hp；阶段切换会重设 HP 或阈值。直接只乘初始 HP 会把增量全部堆在第一段，因此本实现把每段需要承受的有效伤害乘以人数倍率，而保留原内部 HP 单位。

每次原版实际伤害 d 进入 `(d*10 + remainder) / denominator`，双人 denominator=15，三人=22，余数留给后续伤害，避免小伤害每帧舍去。阶段编号、结束阈值变化或 phase_frame 回退会清余数；换关也清空。分数仍由原始命中流程结算。计时触发的切阶段及纯计时的脚本 HP 变化不修改。

核对的原 image-relative 补丁点：

| 地址 | 路径 | 处理 |
|---|---|---|
| 0x1E5F9 | 公共 boss_hittest_shots_damage | 调用原完整命中计算后按人数结算；无敌音效路径不累计余数 |
| 0x1B404 | Boss 另一身体判定，伤害同样扣 DS:53D6 | 使用同一 Boss 阶段余数 |
| 0x179DF | 魔理沙额外阶段减伤后的扣血 | 在原整数除法之后结算；公共 helper 通过已核对返回地址跳过重复缩放 |
| 0x1426B | 第一关道中 Boss 直接命中路径 | 道中 Boss 独立阶段余数 |
| 0x1E634 | 公共 midboss_hittest_shots_damage | 道中 Boss 独立阶段余数 |

0x1BBDE 命中结果用于改变 DS:46F2（运动速度），不是 Boss HP，保持原样。0x16D14 / 0x1A1DB 的可击打弹体与 0x17F17 的杂鱼也保持原样。0x1C50B 是按阶段进程写入 HP 的脚本逻辑，不把它当作玩家伤害缩放。

因此原画面血条继续显示原版比例，不直接显示 1.5/2.2 倍的内部数字；每个可扣血阶段需要的实际累计伤害变为相应倍率，存在原版整数 HP 的最小单位取整。
