# 首次公网验证

2026-10-04。用户已确认局域网实际游戏测试正常，进入异网验证。先测 STUN 直连，不预设需要购买服务器；本轮未配置 TURN，也不保证所有运营商网络能直连。

## 操作

1. 在 Windows PowerShell 执行 `winget install --id Cloudflare.cloudflared --exact` 安装 Tunnel 工具（已安装且 PATH 可找到时跳过）。安装后重新打开终端/启动脚本。
2. 运行 `start-lan.bat`。若现有服务窗口已经运行，先关闭旧服务窗口再重启，保证使用最新构建；不要同时启动两个占用 9866 的服务。
3. 双击 `start-public-tunnel.bat`，找到输出中的 `https://随机名称.trycloudflare.com`。
4. 在地址后添加 `/lan.html?network=public-test`，将完整链接发给另一端。双方都打开同一个完整 HTTPS 链接。该参数仅选择固定 STUN 测试配置，不接受任意服务地址或密钥。普通 lan.html 不改变配置；大项目已注入配置时优先保留其配置。
5. 电脑继续使用家庭宽带；手机关闭 Wi-Fi，使用 4G/5G。也可两台电脑分别用不同宽带/手机热点。不要以同一 Wi-Fi 验证结果代替公网验收。
6. 正常建房、选座、准备、开局。首测保持上次成功的座位和建房顺序，只改变网络。刷新或结束返回会保留 public-test 参数，因此不再需要控制台设置 STUN。
7. 查看诊断：应显示 STUN 地址 1 / TURN 地址 0 / 策略 all。观察候选类型与最终连接路径，连续玩 10–15 分钟，记录 RTT、相同状态步、等待及异常。仅看到 srflx 候选不算连接成功。

## 失败与结果

- HTTPS 页面打不开：先保存 Tunnel 输出及网页错误，尚未到 WebRTC 阶段。
- 建房/加入错误：保存页面提示，检查房间接口和代理下的 Origin/Host；不直接认定 NAT 穿透失败。
- 已加入但 ICE 超时：保存双方候选类型、服务错误、配置摘要及停止原因。只有 host 候选可能是 STUN 访问未成功；即使有 srflx 也不保证能直连。必要时下一阶段使用托管 TURN。
- 异网正常游戏、状态校验持续一致：本组网络的公网直连通过，不能推广为所有网络通过。需要覆盖更受限制网络时再验强制 TURN。

Tunnel 代理网页、资源和 HTTP 房间服务，不承载 WebRTC 游戏数据，也不能代替 TURN。服务窗口和 Tunnel 窗口必须持续开着。停止 Tunnel 即撤销本次临时入口；新开 Tunnel 的域名通常不同。该入口会公开 web 目录下的资源和房间 API，链接只给测试伙伴。没有开放磁盘其他目录，也没有添加账号或长期公网部署。

## 本轮实现与验证边界

lan.js 增加显式 public-test 配置入口，room.js 返回时保留模式，构建指纹覆盖 lan.js。新增独立 Tunnel 启动脚本，未修改回滚、输入消息或局域网默认 ICE 配置。只做静态检查和构建；公网连接和游戏由用户实际验证。cloudflared 是否已安装、可访问及运营商直连能力不以代码检查替代。
