# NP21 性能优化验证（2026-10-07）

## 发现与修改

实机电脑 Edge 中第一关保持自动射击，CPU 采样热点包含 WebAssembly.Table.get、getWasmTableEntry、invoke_v 与 WASM 游戏执行。主要可消除开销是对不变函数表重复调用浏览器接口。

- 新增逐模拟器实例的静态函数表缓存，应用于本地/单机与联机生成适配器。
- 构建只接受已审计的原版 WASM SHA256 `d64bbe39549a48686b1ed04fbadec68d8b33643d220395a9c09b8d54834f36e4`。上游文件不改；不修改游戏数据、CPU 时钟、函数实现或异常路径。
- 本地合作使用已验证的输入地址，无地址时每帧最多查找 1 MiB，跨块重叠；删除每秒全堆遍历。
- 本地合作每帧只建立一次状态快照；折叠的诊断面板不生成文字，展开后最多每秒 4 次；手柄设备列表最多每秒 4 次，实际输入仍每帧读取，说明文字只在变化时写入。
- 共享触摸控制缓存画面尺寸，ResizeObserver、窗口/全屏变化后失效。拖动不再每次同步读取布局。保留原灵敏度、移动范围、Bomb、双指低速与布局编辑。

## 性能测量

同机先后各运行一次、第一关持续开火，每段约 7 秒；计时窗口不启用 CPU Profiler。另开 2 秒 Profiler 窗口只查热点，避免把采样器的额外开销算入更新耗时。原查询通过测试专用浏览器路由恢复，缓存查询使用同一 NP21 二进制。

| 常速桌面浏览器 | 原查询 | 缓存查询 |
| --- | ---: | ---: |
| 模拟器更新次数 | 420 | 421 |
| 平均更新耗时 | 12.61 ms | 9.10 ms |
| P95 更新耗时 | 16.10 ms | 12.60 ms |
| 观察到的游戏帧增量 | 396 | 396 |

此次平均耗时减少约 28%，P95 减少约 22%。这是模拟器回调耗时，不是整页耗时或帧率增幅；单次对照受系统负载、游戏进度与 JIT 影响。首次启用 Profiler 的探索记录不用于上述性能结论。

额外的 CDP 2 倍 CPU 节流压力窗口中，两种版本都出现严重补帧；缓存版本有改善但仍未稳定 60 帧。不将这种人工节流结果推算成具体手机性能。普通本地渲染走 GPU 路径，测试中的软件 Canvas 提交探针未命中；本次没有基于该空结果修改像素路径。

## 正确性验证

- CDP 反汇编审核共 485169 行，未发现 table.set/init/copy/fill/grow。固定表 2244 项，生成器拒绝不同 WASM 哈希和 JS 表写入。
- 函数表测试：实际 WASM 函数身份、调用结果、空项、越界异常及实例隔离均通过。
- 真实 NP21 联机适配器：原查询与缓存查询运行相同输入，从启动到实际游戏，检查点校验和一致；分别保存快照、运行 12 步、恢复重放，校验和一致。
- 单机浏览器：原版开头、标题、触摸菜单与移动、暂停/恢复、两项判定点偏好、返回标题通过。
- 共享触摸浏览器：横竖屏布局、双击 Bomb、多指、偏好持久化和本地合作进入关卡通过。
- 60 Hz 调度、2/3 人回滚队列、native 快照测试通过；JS 语法与生成文件摘要校验通过。

工具位于 tools/profile_solo_browser.cjs、audit_np21_table.cjs、test_np21_dispatch.mjs、test_dispatch_browser.cjs。浏览器工具要求先从工作区启动 9886 QA 服务器。TABLE_CACHE=0 测原查询，默认测试当前缓存版本。

未完成手机真机对照、全部关卡或真实多端网络压力验收。仍保留 60 Hz 呈现上限。若手机仍卡顿，下一步应取得具体设备上的 native 回调耗时和帧间隔，再决定是否需要更深层的 WASM 编译优化；不通过删弹幕或降低游戏速度制造流畅假象。
