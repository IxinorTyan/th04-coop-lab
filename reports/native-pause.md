# 原版暂停接入

2026-10-03。用户要求使用游戏内暂停，保留联机权限及退出行为。

## 实现

- 保留原版 MAIN image `0xB2CF` 暂停函数的标题、继续/退出文字、选择重绘和清除菜单逻辑。入口 `0xABAE` 加 near wrapper 标记原生暂停活动状态。
- 仅暂停函数内的输入调用 `0xB2D7`、`0xB31B`、`0xB3A7` 接入桥接。桥接启用时，两次松键检查清空原生 key_det；菜单等待每次调用原版 frame_delay(1)，从同步命令读取选择和继续状态。选择变化交给原版菜单执行；继续发送原版 CANCEL，强制返回继续。
- 桥接四字节依次为 enabled / requested / selection / active，地址由构建清单 native_pause_cs_offset 提供。原生内存随现有完整快照回滚；JS 权限状态沿用原有快照及状态摘要。
- 第一个实际游戏帧之后才启用桥接。任何座位的暂停请求转为原版 P1 Esc；原生入口确认后松开 Esc。暂停期间继续执行模拟器，关卡停在原版暂停函数中；屏蔽各玩家战斗输入。原生暂停尚未退出时也不允许新增预测。
- pause.js 只保留同步权限和命令判定，不再显示 HTML 菜单或停止模拟器。房主可选择退出，客机确认始终表示继续；同时继续与退出时仍按原规则优先继续。退出沿用已确认帧效果，由房间关闭全员 iframe，不把退出命令提交原版返回标题的分支。
- 客机看到与房主相同的原版菜单（包括退出文字），但无法操纵退出项。键盘和手柄映射不变。
- 单机入口不启用桥接，暂停输入调用回退原函数。三处被替换 far call 的 MZ 重定位移除，新增原版输入/帧等待指针按插入大小和加载地址重定位。新增代码继续共用已有插入槽+DOS 堆总预算。

## 构建及验证边界

构建：`python tools/build_lab.py --keep-vendor`，再执行 `python tools/build_lockstep_runtime.py`。执行 JS 语法检查及 Python AST 静态检查，不运行游戏、浏览器或任何测试。

尚需用户人工验收：2P/3P 任意座位暂停；房主选中退出时客机确认仍继续；手柄 Start/A；暂停后保持按键再松开；连续暂停/继续；房主退出关闭全员游戏；单机原生暂停照常工作。没有运行验证记录。
