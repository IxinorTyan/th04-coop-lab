# 掉线同步与离线幽灵

2026-10-03，协议 th04-rollback/2。实现已构建，未运行验收。

## 对玩家的行为

- 主机角色的连接超时：客机停止模拟、关闭游戏 iframe，显示断开原因。权限跟随 host 身份，支持主机选择 P2 或 P3。
- 通道断开先留 5 秒恢复时间；静默连接在 3 秒没有消息后进入同样的 5 秒等待。短暂断链恢复后，通过每秒一次的最近 32 步输入补包补齐漏发操作。网页隐藏但仍发心跳不算掉线，沿用隐藏页面停止模拟的行为。
- 客机确认掉线：主机指定统一步号，永久停止等待该座位的输入，其后视为零输入。3P 可退为两人，之后可退为主机独自继续；开局人数和 Boss 倍率不变。
- 离线座位显示幽灵和 OFFLINE 标签，不参与移动、射击、碰撞、道具拾取、救援或给命；1UP、过关和续关也不复活该座位。保存原有资源和座位，未实现重连接管。已有子弹或 Bomb 效果不会因断线立即撤销。
- 掉线时若处于原生暂停，暂停保持，在线玩家可继续或由主机退出。离线状态在关卡继续时应用并显示。
- 全员资源就绪并开始同步之前断线，仍停止开局并要求重建房间。服务不可达会先重试，持续失败关闭本局；单次 HTTP 请求仍有 10 秒超时，因此服务断线提示不保证恰好 5 秒。

## 同步边界

`room.js` 的 membership 协商只接受房主发起。余下玩家冻结采样与模拟，报告模拟步、输入确认前缀及近期真实输入。`membership.js` 合并报告：保留任一存活端已收到的离线玩家真实输入；只有无人收到的未确认空缺补零。冲突输入或超出 32 步保留窗口则停止，不强行覆盖已确认状态。

离线生效步取各报告模拟步的最大值，不回写已执行的离线状态。缺失输入补齐仍可能触发原来的预测纠正，随后在生效步起使用相同的离线掩码。队列中的离线时间表不回滚，属于已确定的控制事件；每次原生执行（含重算）根据步号写入对应掩码。剩余玩家的状态校验继续运行。

三人客机之间的直连如果持续断开，由报告客机请求房主排除对端；当前没有自动改走中继的功能，即便对端到房主仍能连接，也可能被移出本局。被移出的页面若还能收到房主通知，会立即关闭本局。协商期间第二位客机也断线，则房主扩大排除名单重新收集报告。未完成协商时不推进游戏。

服务端客机 leave/drop 只撤销身份，保留锁定座位；不再把整局标为 ended。主机 leave 仍删除房间。加入接口仍只允许 lobby，不允许重新加入正在进行的对局。

## 原生状态

`patches/offline.asm` 使用独立 offline_mask 和 R_OUT=2（普通死亡幽灵为 1）。在原生输入读取后、世界更新前设置死亡/无敌标记并清除该机体激光和操作。原生暂停返回后也应用一次，避免在暂停期间掉线后仍多参与一帧碰撞。

resource_store、seed_resources 保留离线资源；救援目标选择、共享奖励、revive_item_player、stage_revive 拒绝该状态。原有 R_OUT 非零判断排除普通碰撞、机体更新、拾取和瞄准候选，继续使用幽灵图层。无重连状态恢复实现。离线效果不会更改 player_count。

新增输入读取 hook 的原始字节、MZ 重定位和指针按构建脚本校验。仍保持插入槽 + DOS 堆总预算为 393728 字节。

## 验证边界与后续入口

按用户要求仅构建、反汇编/源码检查、JS 语法与 Python AST 检查；没有执行测试、模拟器、浏览器。`tools/test_departure.mjs` 是未执行的队列回归源文件，覆盖各主机座位、末帧输入只到一台、两次掉线、启动锁步及冲突拒绝。

人工验收重点：主机关闭页面/断网；2P 客机退出后主机独自继续；3P 任一客机以及两位客机先后退出；主机占 P2/P3；暂停期间掉线；离线队友不可救且过关不复活；剩余玩家全部死亡及续关；掉线前后不同机的状态校验一致。后续重连需要独立实现身份验证、完整状态传输和接管生效步，保留座位并不意味着已经支持重连。
