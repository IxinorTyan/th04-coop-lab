## 当前交接状态（2026-10-04）

本项目可以进入主项目集成与性能验收阶段：同屏、LAN 和 NP21 预测回滚已有实现；用户已实测公网 WebSocket 双人进入游戏。**不是已完成流畅度验收或已兼容 eagler-touhou 正式服务器的版本。** 当前协议为 `th04-rollback/2`，下方 `/1` 和 `lockstep` 等描述均属历史。

- 现有 LAN 默认不配置 STUN/TURN，使用可靠有序 WebRTC 通道；公网 `network=public-ws` 使用临时 WebSocket 中继，不需要 TURN 账号。两种模式独立，当前不自动直连失败转中继。
- 最新用户反馈：PC 客机 P2 约 30.6/60 同步步/秒，应用层 RTT 933.5ms，模拟含呈现 11.8ms/步、快照 2.4ms/次，预测允许且领先 12/12 步，快照约 246MiB。用户仍感觉延迟大；这是一份 PC 瞬时记录，没有同期手机数据，不代表稳定帧率，也不能把相对早先 2–4 步/秒的变化全部归因于代码调整。

### 当前启动方式

1. 同屏使用 `start.bat`；LAN 使用 `start-lan.bat`，房间服务端口 9866。
2. 公网 WebSocket 需安装 `requirements-relay.txt` 中的依赖和 cloudflared；保持 `start-lan.bat` 运行，再启动 `start-public-tunnel.bat`。
3. 等 Tunnel 出现 `Registered tunnel connection` 后，从项目根目录 `public-test-url.txt` 复制完整链接给双方，链接应以 `/lan.html?network=public-ws` 结尾。Quick Tunnel 重启会换域名；文件只记录地址，不能证明连接仍在线，强制关闭窗口后尤其可能残留旧地址。1033 表示当前域名没有可用 Tunnel 连接。
4. 双方刷新、重建房间，开局后确认出现“性能诊断 v1”。不同网络正常战斗时记录两端诊断；不要以暂停菜单中的低步速衡量战斗性能。

## 上轮双人玩法修改（历史记录，2026-10-03）

- 幽灵在背景 / Bomb 背景之后、敌方弹幕之前绘制，降低遮挡。
- 救起幽灵：复活者 Bomb 设为 1，施救者保留 `floor(当前 Bomb / 2)`，即扣除一半向上取整；0 Bomb 仍可救。给活着的队友命不扣 Bomb。两种操作仍扣施予者一条备用命。

### 当前音乐实现与必须保留的修复

原游戏 **BGM=0，SE=1（FM 音效）**；浏览器独立播放 BGM。音量滑块只控制浏览器音乐，原 PCM 播放器继续输出游戏音效。

**配置校验和是已查明的失败原因。** MIKO.CFG 共 10 字节：前 6 字节为选项，偏移 3/4 为 BGM/SE，偏移 6–7 为 resident 段，偏移 8 为 debug，偏移 9 为前六项之和。此前只改 3/4，没有更新 9；`ZUN -S` 检测校验失败，重建默认值并重新打开 BGM。必须同时更新 3、4、9，不能破坏 resident 指针。依据 `reference/ReC98-master/th04/res_huma.cpp`、`formats/cfg.hpp`。

`tools/lan_sound_config.py` 读取已校验 FAT12 磁盘定位配置和 MAIN，生成 `runtime.json.native_sound`（schema 2）。浏览器先逐字节检查原值，再应用编辑；两端共同开局比对相同策略。

为保留切曲通知而不安装 TSR，在私有 MAIN 副本中对 `snd_kaja_interrupt` 做等长 23 字节替换：原 image-relative 地址 `0x133DF`，实际文件位置须加清单中的 `insert_size`（当前 `0x3000`）和 MZ header。原 BGM OFF 分支是 no-op；新分支记录 AH=00/01/02/19（播放/停止/淡出/音量），保留原 AX 返回语义，其他查询仍为 no-op，SE 走另一条原生路径。

| 当前 MAIN 的 DS 偏移 | 含义与约束 |
|---|---|
| `0x08F4` / `0x08F5` | 实际 SE / BGM 模式，页面直接读取显示 |
| `0x3964` | 当前加载曲名；`snd_load` 在 BGM OFF 提前返回之前仍写入这里 |
| `0x08F8` / `0x08FA` | 通知序号 / AX 命令；复用 BGM OFF 不会访问的 `SND_LOAD_EXT[0]` 指针空间 |

这些偏移有构建时二进制锚点校验，只适用于当前 MAIN。**该通知区仅在 BGM=0 时可复用，不可直接打开原 BGM 或迁移到 OP/MAINE/其他版本。** 同一模拟步多条命令以最新一条为准；当前不是完整事件环形队列。结局程序和完整通关仍需另外适配、验收。

`runtime.js` 只读这些游戏字段，缓存音乐模块加载期间的指令，再交给浏览器播放。使用 Web Audio 的循环源，不按游戏步补音乐、不逐帧追赶播放位置。实际 BGM 非零时报告错误，避免叠加两路音乐。两台电脑音乐位置允许不同，不进入同步摘要。

## 当前操作与规则

- P1：方向键、Z 射击、X 炸弹、Shift 低速。
- P2 键盘：WASD、J 射击、K 低速、L 炸弹。
- P2 标准手柄：左摇杆 / 十字键、A / × 射击、B / ○ 炸弹、RB / R1 低速。
- 火力、射击等级、火力溢出奖励计数、炸弹和残机分别保存。分数、点、梦和擦弹暂时共享。普通敌弹的擦弹标记按玩家独立保存，同一颗弹可以被双方各擦一次；P2 擦弹同步增加共用擦弹数、刷新原版擦弹栏，并按当前难度增加擦弹分数，遵守原版每关 999 次上限。双方调用各自原版的完整射击等级表，恢复 P2 子机；激光的时间、样式、位置和环形弹计数分别保存。共享普通子弹池只更新一次。
- 两人均可拾取道具，Power 归拾取者；1UP 给所有玩家各加一命，已退场者在自己的出场位置复活，并获得 150 帧无敌，保留原有火力和炸弹库存；Bomb 道具给仍在场的玩家各加一颗，不奖励已退场者。同一道具的分数、音效和移除只结算一次，库存分别封顶（生命含当前最多 100，炸弹最多 99）。共享分数 Extend 和过关炸弹奖励仍只给在场玩家。
- 场上仍只有一套炸弹效果；生效期间另一人按 Bomb 不消耗库存，也不能覆盖施放者。不同角色的 Bomb 背景板和角色图形在开局预载；每次 Bomb 的背景、角色演出和函数跟随施放者，绘制结束后恢复 P1 的全局上下文。普通死亡后的复活按原版设置补充该玩家的炸弹；1UP 救回已退场队友不额外补充炸弹。
- 残机耗尽后，在自己的初始位置（P1：144,320；P2：240,320）变为对应角色的小幽灵，缓慢上下漂浮，不碰撞、不拾取、不射击，也不被选作自机狙目标。两人均退场才进入原版 Game Over / Continue。队友拾取 1UP、借命或打通关卡都可以救回退场者；选择续关时一起恢复。
- 借命：有备用残机的存活玩家，低速且停火靠近队友（包括幽灵），保持 90 个游戏帧。范围沿用 TH04 普通敌弹擦弹的 36×44 像素区域；分数上方的 RESCUE 栏显示百分比和彩色进度条。完成时给予者扣一条备用命，目标加一命；幽灵复活并获得 150 帧无敌。完成后必须松开低速键才能再次借命，射击、受击、离开范围会中断。对活着的队友直接转移生命，不生成共享 1UP 道具。
- 过关炸弹奖励后，已退场玩家免费恢复一条当前生命，Bomb 设为 1，不扣队友残机。幽灵贴图由 PC-98 GRCG 原生绘制，位于敌方弹幕下方；读条由文字显存绘制，按关卡现有调色板匹配颜色，不修改地图配色。
- 常规自机狙和已接入的 Boss 角度计算，以及道具吸引，选择距离更近的非死亡玩家；等距选 P1。固定弹幕仍保持原设计。
- Boss 接触、特殊激光等 P2 碰撞仍未完整适配，尚不作为完整通关版。

## 原生资源栏与扩展边界

右侧仍在游戏内绘制，每个玩家两行：第一行 `P1 [大 P 道具] 0.03`，第二行 `[1UP 道具] 02 [Bomb 道具] 03`。直接调用原版道具精灵（PAT_ITEM + 3/5/4），数字使用 PC-98 原生文字层。Power 显示为 `floor(原始值 × 100 / 32) / 100`，即 0.00–4.00；底层仍是 0–128 和原版九个升级阈值。1UP 旁显示备用残机（内部数值减一），0 仍有当前这一命；耗尽后显示 OUT。借命期间在分数上方（文字第 0–2 行）显示 RESCUE 标题与 1>2 / 2>1 的百分比、彩色进度条；读条轻微闪动，完成后变绿，不占用原有数值区域。

资源表采用 16 字节固定步长，预留四槽位；HUD、团队奖励和存活遍历使用玩家数量。本轮已扩展运动、输入、普通碰撞和状态切换以支持 P3；P4 未实现。

Boss 血条移到原单人火力条位置（文字行 21/22），分数、点、梦、擦弹、难度保留。右侧显存也是原版背景贴图缓存，因此空白文字格必须使用 `TX_BLACK | TX_REVERSE` 遮罩；透明空格会把缓存暴露成滚动图案。玩家栏可见字符限制在缓存区左侧，留白保持不透明。

每个图标只开放两个透明文字格。图标绘制使用原版滚动坐标转换，保持固定屏幕位置；每帧只清理 x=448–527 的专用图标列，移除滚动残影，不触碰 x≥576 的贴图缓存及 x<416 的游戏区域。

### 关间加载内存回归

双角色需要常驻第二套 Bomb CDG（52608 字节）、BB（2048 字节）和自机 BFT。原版固定 320000 字节内存池不足以加载第二关：NP2 故障现场只剩 320 字节，ST01.MAP 需要 4160 字节。原版地图加载器不检查分配失败，会把数据写到 0000:0000，覆盖中断表，停在关间标题画面。

构建器将原版内存池扩大 64 KiB，合计 385536 字节；不改关卡流程、复活或贴图。此预算在随附 DOS/NP2 环境中验证，不能直接假定适用于其他启动环境。

`python th04-coop-lab/tools/test_stage_memory_cpu.py` 用真实 ST01.MAP 和原版 16 位地图加载器、内存分配器，复现旧预算覆盖中断表，并确认新预算完整加载地图且不破坏中断表。浏览器 `?qa=rescue` 的“进入下一关”按钮设置原版 Q_NEXT_STAGE，再检查新关卡游戏帧恢复；这是关间清理/加载验证，不等同于完整击破 Boss 通关。

### 全模式 60 帧上限

原版单机、本地合作、联机均默认使用 60 Hz 画面更新上限，高刷新率屏幕不再额外执行画面更新。原版模拟器仍按实际经过的时间运行；联机的 60 Hz 逻辑步、补步与回滚保持不变。设备负载过高时仍可能低于 60 FPS。

单机运行时复用已验证的输入内存地址；需要重新查找时每次仅扫描 1 MiB，避免每秒集中遍历整个模拟器内存。

单独重建本地限帧适配器：`python tools/build_frame_runtime.py`。联机构建器 `python tools/build_lockstep_runtime.py` 也会生成它。限帧调度测试：`node tools/test_frame_limit.mjs`。


2026-10-07 性能优化：单机、本地合作与联机的模拟器均缓存静态函数表查询，减少高频 JS/WASM 接口开销。本地合作不再每秒扫描整个内存，折叠诊断不刷新；触摸移动复用画面尺寸，仅布局变化后重新测量。电脑上的单次第一关开火对照中，模拟器平均更新耗时约从 12.6 ms 降至 9.1 ms；这不是手机帧率保证。详情见 `reports/performance-2026-10-07.md`。
