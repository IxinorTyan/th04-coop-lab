## 对照来源

`../../th06-eagler/th06-eagler/src/netplay/Th06LanStageProbe.cpp`：

- 初始化 `CoreConfig` 使用 inputDelay=0、maxRollbackFrames=12、方向最多预测 3 帧，并限定可预测按钮。
- `SendLocalFrame` 只采样一次，`SendScheduledLocalFrame` 重建带历史输入的网络包，不重新读取同一逻辑帧的操作。
- 正式 LAN 路径逐同伴发送，并有 `SendRepairTo` 可靠补包；三人测试 relay 路径明确保留 32 帧冗余。
- `Th06RollbackState.cpp` 负责原生游戏回滚状态。TH04 当前的 NP2 JS 适配没有同等完整快照接口；仅复制 DOS 内存不能恢复 CPU、硬件、中断、音频和确定性时钟。因此本轮不添加未经完整快照支持的预测。

## 现有瓶颈与修改

1. 旧操作和控制共用可靠有序通道，一个丢包可能阻挡后续操作。现在 `th04-control` 保留可靠有序的开局/校验/结束消息，`th04-fast` 使用 ordered=false、maxRetransmits=0。每个操作包附最近 8 帧；缺包停顿每 40 ms 重送，持续 200 ms 后可靠补最近 32 帧。快速通道不可用时可走可靠通道。可靠连接/整条 peer connection 断开仍按原规则结束房间。
2. 三人客机之间直连可能明显慢于到房主的连接。客机自己的包发给两个同伴，房主验证来源座位后转发给另一个客机；接收方取最先收到的不可变输入，重复相同内容无副作用，冲突的待执行输入中止。只有房主有转发权限，禁止冒充自己的座位、未知槽位、越界帧以及无界包。
3. 全员加载完成后，房主收集到每个客机的 3 个 RTT 样本，或最多等 1.5 秒，再统一下发 delay。用近期样本中位数估算；三人采用两条房主链路 RTT 之和作为转发路径预算。delay=ceil(RTT/2/16.67)+1，限制 2–12；缺样本默认 4。配置只在帧零建立，所有玩家消费同一 delay，运行中不各自调整。
4. 旧调度使用进入 pump 时的 accumulator 计算下次等待，忽略已经花在 WASM 上的时间。当前扣除整个 pump 已耗时；仍保留最多 4 步、6 ms 后让出事件循环（单个原子步骤可能超过 6 ms）的约束。
5. 诊断显示实际协商缓冲、真正新增输入数、直连/转发先到计数、等待时长。输入到应用耗时从本次不可变帧采样起算，避免长按后再次变化时出现无意义的大数。RTT 包含浏览器主线程排队，不能视为纯网络时延。

## 正确性与发布边界

协议提升至 `/3`，旧页面不能混入。`input-wire.js` 哈希进入开局版本比对，生成器同步更新联机清单。保持 native EXE、磁盘、暂停权限、Boss 倍率和确定性模拟时钟不变；缺少任一真实输入依然等待，每 120 步继续比对状态。

无序输入可能先于可靠 RUN 到达，队列允许先缓存实际输入，再补统一数量的起始空帧。转发只由房主执行一次，避免循环。补包重用不可变历史，不把当前按键写回旧帧；本地保存 32 帧，大于最大输入领先窗口。未收到输入时仍定时重发，避免最后一包丢失后所有人永远等下一包。

新增 `tools/test_input_wire.mjs` 覆盖 2/3 人各延迟、丢包/乱序/重复、最后一包可靠补发、边界拒绝和 RUN 前输入缓存；只做语法检查，未执行。现有回归脚本也未运行。

人工验收重点：先确认本地和多人均可进入游戏；观察三端相同状态步持续增加；比较同步步速率、平均执行时间、当前等待和转发计数。正常 LAN 的目标是接近 60 步/秒、2 步缓冲，但尚无实测保证。若单步模拟持续超过 16.67 ms，需另做 NP2 执行/呈现性能优化；本改造不能消除真实计算成本，也没有 TH06 的零延迟预测体验。
